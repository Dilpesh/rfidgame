226## 21. Cards are global — one registry, not one map per game
227 
228Found 2026-09-25, in `jungle-rescue-english`. It read its cards from
229`localStorage['rescueGameCards']` — Jungle Rescue 2's key, on the same origin —
230and only filled in gaps. JR2 had already written `6373651 → SNACK` and
231`6374815 → FIRSTAID`, so on any phone that had ever opened JR2 both biscuit
232cards and the first-aid card came back as "wrong card". Nothing in the code
233looked wrong; the bug lived in another game's storage.
234 
235The rule, as Dilpesh put it: **a card means the same thing in every game.**
236So the browser keeps one registry, `docs/card-registry.js`, under one key
237(`kahaniCards`), seeded from the block `sync_cards.py` writes into it from
238`cards.json`. A game never sees a UID. It asks
239`CardRegistry.lookup(raw)` for the canonical card (`SNACK`) and maps that to
240its own id through its generated `CARD_MAP` (`SNACK → BISCUIT` here,
241`→ snack` in Hinglish, `→ biscuit` in Toy Town). Teach a card once, in any
242game, and every game knows it.
243 
244Seeding: on a new `seed_version`, `cards.json` wins for the UIDs it names
245(an edit there must reach every phone); between seeds, `teach()` wins; UIDs
246taught by hand that `cards.json` does not know survive a re-seed.
247 
248A new story that needs a card `cards.json` does not have fails in
249`sync_cards.py` with the card named, until it is added there under a
250canonical name. Cards are global; a story only says which ones it uses.
251 
252`check_games.py` gates on `CardRegistry.lookup`. The six older games are
253excused by name until each is migrated — `moon` and `jungle-rescue` first
254(same shape), then `banana-rescue`, `jungle-rescue-hinglish`, `toy-town-v2`,
255and `toy-town` last, since it is the A/B control.
