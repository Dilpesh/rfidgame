14The shared registry
15-------------------
16A card means the same thing in every game, so the UIDs live in ONE place in
17the browser too: docs/card-registry.js keeps a single localStorage key for the
18whole site, seeded from the block this script writes into it. A game on the
19registry never sees a UID — it gets only a small generated CARD_MAP
20(registry card -> the id that story uses, e.g. SNACK -> BISCUIT), also written
21from cards.json. Games are moved onto the registry one at a time; the ones
22listed in REGISTRY_GAMES are on it, the rest still get the older per-game
23uid -> card block.
24 
25A new story that needs a card that is not in cards.json fails here, with the
26card named, until it is added to cards.json under a canonical name. That is
27the rule: cards are global; a story only says which of them it uses.
